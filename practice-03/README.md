## Организация кода

| Файл | Ответственность |
|---|---|
| `src/data.js` | общий набор `demoTasks` и `variantTasks` варианта 4, номер варианта |
| `src/task-service.js` | прикладные функции ПР2: создание, поиск, отбор, сводка, изменение, удаление |
| `src/task-selectors.js` | `getVisibleTasks(tasks, filter)` — вычисление видимой выборки по фильтру, без изменения данных |
| `src/task-view.js` | `createTaskElement`, `renderTaskList`, `renderSummary`, `renderEmptyState` — создание DOM и обновление представления |
| `src/main.js` | состояние (`currentTasks`, `currentFilter`), распознавание действий, вызовы сервиса и отрисовки, подписки на события |

Полный список задач хранится в `currentTasks`, выбранный режим — в `currentFilter`
(обе переменные в `main.js`), видимая выборка каждый раз вычисляется заново через
`getVisibleTasks` и в `currentTasks` не записывается. События обрабатываются на контейнерах:
`ul#task-list` и `#task-filters` получают обработчики один раз при запуске, вне `renderApp`.
Сводка вычисляется в `task-view.js` через `getTaskStats(currentTasks)` по всему текущему
массиву, а не по количеству карточек в DOM.

## Индивидуальный вариант

Тема варианта 4 — подготовка семинара. Исходные шесть задач (`?dataset=variant`):
`11` Определить тему семинара (`medium`, выполнена), `23` Собрать материалы для доклада

| Этап | Всего | Выполнено | Осталось | Прогресс | Видимые id |
|---|---|---|---|---|---|
| До действий, «Все» | 6 | 3 | 3 | `50.0%` | `[11, 23, 37, 41, 58, 64]` |
| Фильтр «Выполненные» | 6 | 3 | 3 | `50.0%` | `[11, 23, 37]` |
| После переключения `id = 23` на «В работе» | 6 | 3 | 3 | `50.0%` | `[41, 58, 64]` в фильтре «В работе» |
| После удаления `id = 37` | 5 | 2 | 3 | `40.0%` | `[11, 23, 41, 58, 64]` |
| Итог, фильтр «В работе» | 5 | 2 | 3 | `40.0%` | `[41, 58, 64]` |
| Итог, фильтр «Выполненные» | 5 | 2 | 3 | `40.0%` | `[11, 23]` |

После переключения `id = 23` набор остался `6 / 3 / 3`, потому что задача была выполнена и
вернулась в «В работе», а `setTaskCompleted(…, 41, …)` не вызывался: одно действие изменяет
ровно одну запись. Удаление `id = 37` уменьшило и общее число, и число выполненных, поэтому
`3 / 6 = 50.0%` сменилось на `2 / 5 = 40.0%`.

## Отладка и клавиатура

Точка останова ставилась на строке чтения идентификатора в `handleTaskListClick`
(`const id = Number(card.dataset.taskId)`).

- до преобразования: `card.dataset.taskId` — строка `"4"`;
- после `Number(...)`: `id` — число `4`, `Number.isSafeInteger(id)` → `true`;
- `button.dataset.action` → `"toggle"`;
- `findTaskById(currentTasks, id)` → объект задачи `id = 4` со `completed: false`;
- после вызова сервиса: `result.ok === true`, `result.tasks` — новый массив из пяти
  записей, `result.tasks !== currentTasks`.

**Отказ для некорректных данных.** В панели Elements значение `data-task-id` карточки
временно менялось на `777` и на `4abc`. В первом случае сервис вернул
`{ ok: false, error: "Задача с id 777 не найдена" }`, во втором идентификатор не прошёл
`Number.isSafeInteger` и функция завершилась до вызова сервиса. В обоих случаях в
`#operation-message` появилось непустое сообщение, а список и сводка остались прежними
(`4 / 2 / 2 / 50.0%`), потому что `result.tasks` не присваивался.

**Клавиатура.** Кнопки карточек и фильтров — настоящие `<button type="button">`, поэтому
активируются с `Tab` и `Enter`/`Space`; нажатие по вложенному `span` обрабатывается так же,
как по кнопке. После изменения статуса фокус возвращается на кнопку той же задачи
(`restoreTaskFocus`), после удаления карточки — на активный фильтр; проверено на `id = 4`
(кнопка осталась активной) и `id = 7` при фильтре «В работе» (фокус ушёл на кнопку фильтра).

## Вывод

Интерфейс получился тонким слоем над проверенным сервисом ПР2: `main.js` только распознаёт
действие и сохраняет новый массив, а вся логика остаётся в `task-service.js`, вычисление
выборки — в `task-selectors.js`, работа с DOM — в `task-view.js`.

Главное различие, которое потребовалось усвоить: изменение данных и изменение DOM — не одно
и то же. Удаление `li` через `element.remove()` убрало бы карточку до первой перерисовки, но
после выбора фильтра запись вернулась бы, потому что массив не изменился. Поэтому действия
идут через сервис, а `renderApp()` заново строит список из данных.

Вторая ошибка, которую пришлось исправлять, — накопление обработчиков: при назначении
анонимных функций внутри `renderApp` после нескольких перерисовок одно нажатие срабатывало
несколько раз. Подписки вынесены из `renderApp` и назначаются один раз на контейнеры
`ul#task-list` и `#task-filters`, а распознавание действия и идентификатора выполняется через
`closest` и `dataset`. Дополнительно пришлось учесть, что `dataset` отдаёт строку: без
проверки `Number.isSafeInteger` значение `4abc` могло бы превратиться в `4`.
