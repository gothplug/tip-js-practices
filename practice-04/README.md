## Эксперименты с формой и хранилищем

Страница `examples/forms-storage.html`, вывод — журнал на странице.

| № | До запуска: прогноз | После запуска: результат | Объяснение |
|---:|---|---|---|
| 1. Пустое обязательное поле | Браузер не даст отправить форму, обработчик `submit` не вызовется | Событие `submit` не возникло (счётчик 0), журнал не изменился: «Действия ещё не выполнялись.»; `validity.valid = false`, `valueMissing = true`, сообщение браузера «Заполните это поле.» | Нативная проверка `required` выполняется до события `submit`, поэтому невалидная форма до обработчика не доходит — это не поломка страницы |
| 2. Название из пробелов | `required` пропустит строку `"   "`, отклонит уже прикладная проверка | До отправки `validity.valid = true`; `submit` получен, в журнале «submit получен, но прикладная проверка отклонила значение.», после `setCustomValidity` — `customError = true`, сообщение «Название не должно состоять только из пробелов.» | Для `required` строка из пробелов не пустая. `trim` — прикладное правило, ошибка ставится через `setCustomValidity` и снимается `setCustomValidity("")` в обработчике `input` (после ввода `valid = true`) |
| 3. Типы значений `FormData` | Значения — строки, `defaultPrevented = true`, название без краевых пробелов | `submit.defaultPrevented: true`, `typeof FormData title: string`, `"  Отчёт  "` сохранено как `"Отчёт"`, приоритет `"high"` | `FormData.get` возвращает строки; `preventDefault` отменяет только стандартную отправку, код обработчика выполняется дальше |
| 4. Строка в `localStorage` и JSON | `getItem` вернёт строку, после `JSON.parse` — объект | `typeof localStorage value: string`, `raw = {"title":"Отчёт","priority":"high"}`, `parsed` — объект с теми же полями | `localStorage` хранит только строки, поэтому запись идёт через `JSON.stringify`, чтение — через `JSON.parse` |
| 5. Повреждённый JSON | `JSON.parse` выбросит `SyntaxError` | «JSON.parse завершился ошибкой: Expected property name or '}' in JSON at position 1 (line 1 column 2)», `raw = {broken-json` | Синтаксическая ошибка — исключение, поэтому разбор находится внутри `try/catch`; без него упал бы весь запуск |

После «Удалить ключ» журнал показал `getItem: null` — отсутствие ключа отличается от
повреждённой записи.

**Итог:** HTML-проверка контролирует структуру ввода (заполнено, число, длина), прикладная
проверка — правила модели (`trim`, уникальность id, допустимый приоритет), а проверка после
чтения из хранилища — что сохранённая строка вообще является JSON нужной версии и схемы.

## Организация кода

| Файл | Ответственность |
|---|---|
| `src/task-service.js` | Чистые операции над массивом задач, включая новую `updateTask`; не знает о DOM и `localStorage` |
| `src/form-validation.js` | `validateTaskDraft` — чистая нормализация и проверка черновика формы, возвращает `{ ok, value }` или `{ ok: false, errors }` по полям |
| `src/task-storage.js` | Схема `{ version: 1, tasks }`, `isValidTaskList`, `loadTasks`, `saveTasks`, `removeSavedTasks`; все исключения storage перехватываются |
| `src/task-view.js` | Карточки (три кнопки), список, сводка, пустое состояние |
| `src/main.js` | Состояние (`currentTasks`, `currentFilter`, `editingId`), режим формы, обработчики, координация сервиса, хранения и отрисовки |

Функции хранения получают `storage` аргументом: так зависимость от браузера видна явно, а
модуль проверяется в Node.js объектом-имитацией `MemoryStorage` и объектами, которые
выбрасывают исключения в `getItem`/`setItem`/`removeItem`.

Данные из JSON проверяются до использования, потому что успешный `JSON.parse` подтверждает
только синтаксис. Значение может быть другой версии, не массивом или содержать задачу с
`completed: "нет"` — такая запись отклоняется целиком, приложение берёт копию исходного
набора и показывает предупреждение.

`updateTask` переиспользует `createTask` для проверки id, названия и приоритета, но из его
результата берутся только `title` и `priority`: значение `completed: false` из `createTask`
не попадает в задачу, статус сохраняется.

| Сценарий | Ожидаемый результат | Фактический результат | Итог |

## Отладка и клавиатура

Точка останова — первая строка после `new FormData(elements.form)` в `handleFormSubmit`.

Успешное добавление (шаг 1 общего сценария):

- сырой `draft`: `{ id: "20", title: "Изучить localStorage", priority: "high" }` — id строка;
- `validateTaskDraft(...)`: `{ ok: true, value: { id: 20, title: "Изучить localStorage", priority: "high" } }` — id число;
- `addTask(...)`: `{ ok: true, tasks: [ ...5 задач ] }`, `result.tasks !== currentTasks`;
- записанная строка: `{"version":1,"tasks":[…,{"id":20,"title":"Изучить localStorage","completed":false,"priority":"high"}]}`.

Повторный id (шаг 2): сырой `draft` `{ id: "4", title: "Дубликат", priority: "low" }`,
результат валидации `{ ok: false, errors: { id: "Задача с id 4 уже есть в списке." } }`.
Выполнение уходит в ветку `showFormErrors`, `addTask` и `saveTasks` не вызываются, строка в
storage остаётся прежней.

В режиме редактирования поле id заблокировано, и `formData.get("id")` возвращает `null`:
disabled-поле не входит в `FormData`, поэтому id берётся из `editingId`.

**Клавиатура.** Форма отправляется событием `submit`, поэтому Enter в поле названия работает
так же, как кнопка. Кнопки карточек — `<button type="button">`, активируются Tab + Enter/Space.
При начале редактирования фокус переходит в поле названия, при отмене и после успешного
сохранения — в поле id. После `toggle` фокус возвращается на кнопку той же задачи, после
удаления — на активный фильтр (`restoreTaskFocus`).

## Вывод

Приложение ПР3 получило форму создания и редактирования, двухуровневую валидацию и
сохранение в `localStorage` без переписывания прежней логики: `main.js` только собирает
черновик, вызывает чистую проверку и сервисную функцию, а затем сохраняет и перерисовывает.

Разделение трёх видов проверки оказалось главным. HTML (`required`, `min`, `step`,
`maxlength`) останавливает явно неверный ввод ещё до `submit`, но пропускает строку из
пробелов, занятый id и программно подставленное длинное значение — это ловит
`validateTaskDraft`. Сервисная операция (`addTask`/`updateTask`) повторно защищает модель.
Проверка после чтения из хранилища отдельна: строка может быть не JSON, другой версии или
с неверной задачей, и тогда список отклоняется целиком и используется копия исходного
набора с предупреждением.

Ошибки, которые пришлось учитывать: пустая строка id не должна становиться `0`; при
редактировании id нельзя брать из `FormData` (disabled-поле не отправляется); `updateTask`
не должен сбрасывать `completed`; сброс удаляет только свой ключ и не сохраняет исходный
набор обратно; фильтр и режим формы не записываются в хранилище.
