## 1. Цель и результат

Собрать интерфейс списка задач на React. Приложение показывает 12 исходных задач и три категории, поддерживает создание, редактирование, переключение статуса, удаление, четыре совместных фильтра и общую статистику. Изменения хранятся в памяти до перезагрузки страницы.

## 3. Компоненты и состояние

| Модуль | Назначение |
|---|---|
| `App` | Хранит `tasks`, `filters`, `editingId` и сообщение о действии. При каждом рендере вычисляет видимую выборку, статистику полного набора и актуальную редактируемую задачу. |
| `TaskForm` | Хранит черновик `draft` и ошибки `errors`. Нормализует значения, передаёт их в `onSave` и очищает форму после `true`. Для `false` показывает ошибку и сохраняет черновик. |
| `TaskFilters` | Получает текущие фильтры и категории, передаёт изменения через `onChange`. Сброс устанавливает четыре пустые строки. |
| `TaskList` и `TaskItem` | Отображают выборку и передают идентификатор выбранной задачи в обработчик родителя. Ключ карточки — `task.id`. |
| `TaskStats` | Отображает число всех, выполненных и активных задач. |
| `domain/task-service.js` | Содержит валидацию, фильтрацию, статистику и операции над массивом. |

При создании id вычисляется как максимум полного предыдущего массива плюс один. Редактирование и переключение возвращают новый массив и новый объект изменённой задачи. Подтверждение удаления выполняется до функционального обновления. Ключ формы равен id редактируемой задачи или `new`, поэтому при выборе другой задачи её поля заполняются заново. Изменение фильтра сохраняет активное редактирование. Ошибки ввода связаны с полями через `aria-describedby` и `aria-invalid`.

## 6. Контрольные вопросы

1. JSX описывает дерево элементов с JavaScript-выражениями. Сборщик преобразует его в вызовы React.
2. Props передаёт родитель. Состояние принадлежит компоненту и меняется через setter.
3. Присваивание обычной переменной не планирует рендер, а локальная переменная создаётся заново при вызове компонента.
4. Функциональная форма нужна, когда следующее значение зависит от предыдущего, особенно при пакетных обновлениях.
5. Копия массива сохраняет ссылки на вложенные объекты. Изменение такого объекта затронет предыдущий снимок состояния.
6. Стабильный ключ позволяет React узнать запись после фильтрации или удаления. Индекс той же записи при этом может поменяться.
7. Выборка и статистика вычисляются из состояния. Отдельные копии пришлось бы синхронизировать.
8. Дочерний компонент вызывает переданный родителем обработчик.
9. Управляемое поле получает `value` из состояния и отправляет ввод через `onChange`.
10. `select` возвращает строку, а модель задачи хранит числовой id.
11. При изменении ключа React размонтирует прежнюю форму и инициализирует новую.
12. Функция обновления должна быть чистой. React может повторно вызвать её при проверке StrictMode.
13. Смотрю на общий счётчик и размер выборки. При `total = 0` нет задач, при ненулевом `total` и пустой выборке действуют фильтры.
14. Тесты проверяют чистые функции. Рендер, клавиатура и сценарии формы требуют отдельного прогона.
15. Массив заменит снимок API. У операций появятся ожидание, обновление данных и обработка сетевых ошибок, а id будет выдавать сервер.
