## 1. Цель и результат

Реализовать API чтения для задач и категорий на Express. Сервер возвращает категории, список задач и отдельную задачу. Запрос списка поддерживает четыре совместных условия. Для известных путей определены ответы на GET, HEAD и OPTIONS. Добавление, редактирование и удаление относятся к следующей практике.

## 2. Запуск

Из папки `practice-09`:

```bash
npm ci
npm start
```

Адрес — http://127.0.0.1:5505/api, проверка запуска — `GET /api/health`. Другой порт можно передать командой `npm start -- 5515`. Для разработки используется `npm run dev`. Чтобы прочитать локальный `.env`, запустить `node --env-file=.env src/server.js`.

## 3. Реализация

| Модуль | Назначение |
|---|---|
| `validation.js` | Разбирает id и параметры списка, отклоняет неверные и повторяющиеся значения. |
| `task-service.js` | Фильтрует переданный массив и ищет запись по id. |
| `store.js` | Создаёт отдельный набор данных для экземпляра приложения и предоставляет методы чтения. |
| `routes.js` | Принимает запросы, вызывает валидацию и хранилище, формирует ответы. |
| `app.js` и `errors.js` | Настраивают общие заголовки и OPTIONS. После маршрутов обрабатывают неизвестные пути и ошибки. |
| `server.js` | Выбирает порт и запускает приложение на локальном адресе. |

Id проверяется целиком по шаблону положительного целого без ведущих нулей, затем проверяется `Number.isSafeInteger`. Параметры извлекаются из `URLSearchParams`, где сохраняются повторы. При обходе имён `Set` отмечает уже встреченные ключи. Строка `false` становится логическим `false`. Значение `null` обозначает отсутствие ограничения. Для поиска обрезаются крайние пробелы, затем сравнение выполняется без учёта регистра с локалью `ru-RU`. Фильтры объединяются через И.

## 4. Контракт

| Запрос | Ответ |
|---|---|
| `GET /api/health` | 200, `{"data":{"status":"ok"}}` |
| `GET /api/categories` | 200, три категории и `meta.total` |
| `GET /api/tasks` | 200, список задач и `meta` с размером выборки и нормализованными фильтрами |
| `GET /api/tasks/:id` | 200, задача в `data`. Для отсутствующей задачи — 404 `TASK_NOT_FOUND` |
| HEAD по этим адресам | Статус и заголовки соответствующего GET, тело отсутствует |
| OPTIONS | 204, заголовки CORS, тело отсутствует |
| Прочие методы на известных путях | 405 `METHOD_NOT_ALLOWED`, `Allow: GET, HEAD, OPTIONS` |
| Неизвестный путь | 404 `ROUTE_NOT_FOUND` |

Пример успешного ответа на `GET /api/tasks/4`:

```json
{"data":{"id":4,"title":"Подготовить модель задач","completed":false,"priority":"high","categoryId":2}}
```

`GET /api/tasks/4abc` вернул 400:

```json
{"error":{"code":"INVALID_ID","message":"Некорректный идентификатор задачи."}}
```

`POST /api/tasks` вернул 405:

```json
{"error":{"code":"METHOD_NOT_ALLOWED","message":"Метод не поддерживается для этого пути."}}
```

`meta.total` показывает размер выборки. При отсутствии совпадений ответ имеет статус 200, `data: []` и `total: 0`.

## 7. Исправленный дефект

POST на `/api/tasks/%ZZ` сначала возвращал 400. Express пытался декодировать параметр пути до проверки метода, и ошибка попадала в обработчик `INVALID_ID`. На этапе маршрутизации такая ошибка для метода записи теперь приводит к 405 с заголовком Allow. GET по тому же пути продолжает возвращать 400 `INVALID_ID`. Оба случая проверены после исправления.

## 8. Контрольные вопросы

1. В Node.js доступны серверные модули, файловая система и работа с процессом. В браузере есть DOM и браузерные API.
2. Путь и HTTP-метод определяют обработчик. Query уточняет условия внутри обработчика.
3. `req.params` содержит переменные сегменты пути, а query — параметры после знака вопроса.
4. Непустая строка `'false'` истинна при приведении к boolean. Нужна явная проверка значения.
5. Полная проверка отбрасывает хвост и ведущие нули. Проверка безопасного целого исключает потерю точности.
6. Коллекция доступна даже при нуле совпадений. 404 означает отсутствие конкретного ресурса.
7. `TASK_NOT_FOUND` относится к существующему маршруту и отсутствующей записи. `ROUTE_NOT_FOUND` означает, что путь не известен API.
8. 405 означает, что путь существует, а метод запрещён. Allow перечисляет допустимые методы.
9. `meta.total` показывает количество записей после применения фильтров.
10. Общие заголовки настраиваются перед маршрутами, обработчик неизвестного пути и обработчик ошибок ставятся после них.
11. Сигнатура `(error, req, res, next)` сообщает Express, что middleware обрабатывает ошибки.
12. Фабрика позволяет тестировать независимые экземпляры и подставлять хранилище. Порт открывается в точке запуска.
13. Клиенту достаточно кода `INTERNAL_ERROR` и общего сообщения. Стек и внутренние данные остаются на сервере.
14. CORS задаёт правила браузерного доступа между origin. Проверка прав пользователя решается отдельно.
15. Нужно добавить POST, PATCH, DELETE, валидацию тела, назначение id, изменить Allow и CORS. Для учебного восстановления потребуется маршрут сброса.
