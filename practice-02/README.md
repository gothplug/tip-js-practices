## 3. Функции, ссылки и копирование

Прогноз заполняется до первого запуска. Для эксперимента 2 необходимо
сохранить исходный результат и отдельно указать результат после исправления.

| № | Прогноз до запуска | Фактический результат | Причина |

| 1 | `sum(2, 3)` → `5`; `sum("2", 3)` → `23` (строка, а не 5) | `5`, затем `23` | Оператор `+` для строки выполняет конкатенацию, а не арифметику: функция не преобразует аргументы сама |
| 2 | `undefined`, потому что в теле функции с фигурными скобками нет `return` | `undefined`; после исправления — `16` | Стрелочная функция с телом в `{}` возвращает значение только по явному `return` |
| 3 | `5` и `true` | `5`, `true` | `alias` и `product` — два имени одного объекта; изменение свойства через любое имя видно через другое |

**Исправление эксперимента 2.** В исходном виде тело `square` состояло из выражения
`value * value;` без `return`, поэтому вызов `square(4)` давал `undefined`. Исправленный

## 4. Модель данных и функции

Модель задачи: `{ id, title, completed, priority }`.

- `id` — положительное безопасное целое (`Number.isSafeInteger(id) && id > 0`), в пределах списка уникален;
- `title` — строка, после `trim()` длиной от 1 до 100; в объект записывается очищенная строка, внутренние пробелы сохраняются;
- `completed` — логическое значение, при создании всегда `false`;
- `priority` — строго `"low" | "medium" | "high"`, по умолчанию `"medium"`.

Распределение ответственности:

| Файл | Что делает | Чего в нём нет |
|---|---|---|
| `src/data.js` | экспортирует `demoTasks`, `variantNumber`, `variantTasks` | функций, вывода, изменения данных |
| `src/task-service.js` | девять прикладных функций над переданными аргументами | `console.log`, DOM, глобального списка |
| `src/main.js` | импорт модулей, последовательность действий, вывод результатов | собственной реализации поиска, фильтрации и расчёта сводки |
| `checks.js` | 35 готовых проверочных сценариев на `node:assert/strict` | реализаций прикладных функций |

Формат результатов: `createTask` возвращает `{ ok: true, task }` либо
`{ ok: false, error }`; `findTaskById` — найденный объект или `undefined`;
`getPendingTasks`, `getTaskTitles`, `getTaskStats` — данные без обёртки;
четыре операции изменения — `{ ok: true, tasks }` либо `{ ok: false, error }`.

**Почему id не равен индексу:** `id` — часть модели записи, он не меняется при удалении
и перестановке элементов, поэтому в общем наборе идентификаторы `1, 4, 7, 10` не совпадают
с индексами `0, 1, 2, 3`. Поиск выполняется через `find` по строгому сравнению, поэтому
обращение к элементу по номеру позиции здесь не работает.

**Почему `getTaskStats` возвращает число, а не строку с процентом:** вычисление и
отображение разделены. `progress` возвращается без предварительного округления
(`3 задачи, 1 выполнена` → `33.333333333333336`), а `toFixed(1)` применяется только при
выводе в `main.js`. Иначе округлённое значение попадало бы в дальнейшие расчёты.

**Какие объекты копируются при изменении задачи:** создаётся новый массив
(`[...tasks]` при добавлении, `filter` при удалении, `map` при обновлении) и новый объект
только изменённой записи (`{ ...item, completed }`). Остальные записи переиспользуются по
ссылке, входной массив и его объекты не меняются ни при успехе, ни при ошибке.

## 9. Вывод

По сравнению с ПР1 появились функции с явными контрактами: результат операции описывается
объектом `{ ok, task | tasks | error }`, поэтому ожидаемые ошибки стали данными, а не
исключениями. Основная работа — возвращаемые значения: `find`, `filter`, `map` возвращают
новые значения, а `result.tasks` — новый массив, который вызывающий код сохраняет только
при `ok === true`.

Неизменность данных проверена двумя способами: сценарием 33 из `checks.js` на замороженных
массиве и объектах (попытка мутации в строгом режиме модуля дала бы исключение) и сравнением
`JSON.stringify` со снимком исходного набора в `main.js`.

Показательной оказалась ошибка с копированием: сначала массив обновлялся целиком через
`tasks.map(...)`, но объект изменённой записи переиспользовался, из-за чего исходная запись
менялась вместе с новой. Помогло создание нового объекта именно изменённой записи
(`{ ...item, completed }`), а не только нового массива. Вторая характерная ошибка —
`priority = null`: значение по умолчанию в параметре срабатывает только при `undefined`,
поэтому `null` должен доходить до проверки и отклоняться.
